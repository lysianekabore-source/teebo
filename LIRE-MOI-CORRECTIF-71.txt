1) POINTS DE SERVICE — POURQUOI ÇA NE MARCHAIT PAS
 Le serveur actuellement EN LIGNE est une version ancienne : il applique
 encore l'ancienne règle (une agence uniquement sous un service) et ignore
 les points de service. Le site, lui, est à jour : il masque donc la
 création des points et affiche « prochainement ».
 Cette version autorise : agence sous Direction Générale, département ou
 service ; point de service sous une agence. Les libellés français
 (« agence », « point de service ») sont acceptés.

2) CRÉATION D'UN UTILISATEUR — BUG RÉEL CORRIGÉ
 Reproduit : créer un compte avec le poste « Président du Conseil
 d'Administration (PCA) » échouait avec « Le format d'une valeur saisie
 est invalide (nombre ou date) ».
 Cause : ce poste reçoit le rôle de surveillance « pca_admin », rôle
 présent partout dans le code mais ABSENT du type de rôle de la base.
 Correction : le rôle est ajouté à la base au démarrage et avant chaque
 création de compte (idempotent). Le compte PCA se crée maintenant
 normalement, avec ses droits limités de surveillance.

3) AUTRES GARANTIES
 • Base ancienne bridant les points de service : le serveur répare la
   contrainte une fois, puis enregistre. Aucune donnée touchée.
 • Refus expliqué : « Une agence ne peut pas être rattachée à …
   Rattachement possible : … ».
