teebo — Console administrateur

Fiche d'écran Version 36 Facturation par module

À quoi sert cet écran : il montre, écran par écran, ce que verra l'administrateur d'une IMF (institution de microfinance) dans la console de facturation teebo, et ce que verra l'équipe teebo côté suivi de toutes les IMF. Les montants sont toujours en FCFA entiers au centime près, jamais de chiffres à virgule flottante. Cinq onglets : Abonnement, Modules, Factures, Statuts de facturation, Journal d'audit. Nouveaute version 37 : la restriction "collecte seule" n'est plus une simple maquette : le bouton existe reellement dans la console et agit sur l'acces de l'IMF. Le blocage est desormais lu a chaque requete sur les vraies souscriptions (aucun cache) : la coupure s'applique a la requete suivante, et la configuration de l'ecran est renvoyee sans memorisation navigateur.

Deuxième essai gratuit refusé. Si l'IMF a déjà utilisé l'essai d'un module, le bouton « Essai gratuit » est désactivé et le message affiché est : « Ce module a déjà bénéficié de l'essai gratuit : il est activé en PAYANT. » La base de données refuse elle aussi l'opération, même si quelqu'un contourne l'écran.
Changement de cycle en cours de mois. Exemple : signature de l'annuel le 16/11. Les jours du 1er au 15/11 sont facturés au tarif mensuel plein (15 jours), les jours du 16 au 30/11 au tarif annuel −15 % (15 jours).   • Un module désactivé renvoie « Fonction non souscrite » à ses utilisateurs, sans les déconnecter.
  • Toute action est enregistrée dans le journal d'audit (qui, quand, quoi).

4.Onglet « Statuts de facturation » — lire une ligne de facture

Chaque ligne porte un statut qui explique d'où vient le montant. Voici les cinq cas possibles.

StatutSignificationExemple chiffré
facture Mois complet, tarif normal (mensuel ou annuel déjà signé avant le mois). 100 000,00 (mensuel plein)
facture_prorata Le module n'a pas été actif tout le mois : activation en cours de mois ou fin d'essai. 25 000 × 10/30 = 8 333,33
facture_cycle_mixte Bascule mensuel → annuel signée ce mois-ci : jours pleins avant la signature, jours remisés à partir de la signature. 37 500,00 + 31 875,00 = 69 375,00
essai_gratuit Essai encore en cours à la date de facturation : 0 FCFA, les jours restants sont reportés. 0,00 (16 jours reportés)
deja_payee Licence unique déjà réglée : aucune ligne à payer. 0,00
Règle de l'essai sur 30 jours, facturé au 14e jour. L'IMF demande sa facture le 14/11 alors que l'essai du module court jusqu'au 30/11. Résultat : 0 FCFA ce mois-ci et 16 jours d'essai reportés. La première facturation se fait ensuite au prorata sur le mois suivant, à partir du 1er décembre.
Calcul du prorata, au jour près. Le premier et le dernier jour comptent tous les deux. Exemple d'un module à 25 000 FCFA activé le 21/11 sur un mois de 30 jours : 10 jours facturés (21 → 30), soit 8 333,33 FCFA. Le jour de signature d'un contrat annuel est déjà remisé.

5.Onglet Acces et restriction — le bouton reel (version 37)

C'est ici que l'equipe teebo coupe ou retablit l'acces d'une IMF, sans attendre un informaticien. Ce n'est plus un dessin : le bouton appelle le serveur et l'effet est immediat pour les utilisateurs de l'IMF.

La page reelle. Elle est servie directement par le serveur, a l'adresse /console-admin (en ligne : https://votre-serveur.onrender.com/console-admin). On y entre l'adresse du serveur, son e-mail d'administrateur teebo et son mot de passe. Rien n'est enregistre dans la page : tout passe par la connexion securisee du serveur.
Ce qu'on saisitOu le trouver
Identifiant de l'IMFLe code court de l'institution (par exemple IMF-0038) ou son identifiant interne. Le serveur reconnait les deux et traduit le code court en identifiant interne. Un code inconnu est refuse avec le message « Aucune institution ne porte ce code ou cet identifiant ».
Motif de la restrictionTexte libre, visible dans le journal d'audit (exemple : essai termine le 30/11).
1. Se connecterAvec un compte de type teebo_admin. Un compte d'IMF ne peut pas ouvrir cet onglet.
2. Lire l'etatLa page affiche, module par module : ouvert, en essai jusqu'au..., ou coupe.
3. Restreindre a la collecte seuleIl reste la Collecte et tontines ; tout le reste est coupe immediatement.
4. Lever la restrictionLes modules reellement payes reviennent ; les essais expires restent fermes.
Bouton de la consoleEffet reel cote serveurCe que voit l'IMF
Restreindre a la collecte seule Une seule operation en base (tout passe ou rien ne passe) : l'acces est marque restreint, l'essai est arrete, les menus sont recalcules dans la meme operation, l'action est inscrite au journal d'audit. Le menu ne garde que Collecte et tontines. Les autres modules repondent fonction desactivee des la requete suivante, avec le motif en clair (acces limite pendant l'essai).
Lever la restriction La restriction est desactivee ; les menus sont recalcules a partir des abonnements reellement actifs. La ligne de menus est creee si elle n'existait pas encore (c'est ce qui rendait l'ancienne version inoperante). Les modules payes reapparaissent. Un module dont l'essai est fini reste ferme, avec son motif.
Lire l'etat Lecture directe en base, sans cache : le navigateur est empeche de garder la reponse en memoire. Rien (lecture seule).
Les trois etats lus par l'ecran, module par module. L'ecran affiche pour chaque module : Accessible (il est actif et, s'il est en essai, l'essai n'est pas termine), ou Coupe (403) avec la raison exacte renvoyee par le serveur (RESTRICTION_COLLECTE_ONLY pendant une restriction, ESSAI_EXPIRE si l'essai est fini, ou « non souscrit »). Deux modules peuvent donc etre dans des etats differents apres une levee : le module paye revient, le module dont l'essai est fini reste ferme.
Garde-fous verifies le 14/11/2026.
  • Sans la table de restrictions installee sur la base, le bouton ne plante pas : il repond que la migration n'est pas encore passee, avec le nom du fichier a executer.
  • Un identifiant d'IMF mal ecrit, ou un code court inconnu, est refuse tout de suite avec un message lisible (et non une erreur technique).
  • La levee repose sur les abonnements payes, pas sur les menus : impossible de rouvrir un module non paye.
  • La page demande confirmation avant toute action destructive.
  • Les reponses sont affichees comme du texte simple : aucun risque d'injection dans la page.
  • Verifie le 15/11/2026 : 39 controles automatiques sur la restriction (39 conformes) et 15 controles de facturation (15 conformes) ; le serveur demarre sans base, /healthz repond, la console s'affiche, et les routes refuse proprement (401) sans connexion.

Garanties techniques visibles dans l'écran.
  • Les montants sont calculés en base de données en décimal exact (jamais en virgule flottante).
  • Un seul essai gratuit par module : la règle est appliquée par la base, pas seulement par le bouton.
  • Factures et lignes verrouillées après génération ; le PDF reprend la ventilation exacte.
  • Le coût annuel affiché est calculé, pas saisi : 75 000 × 85 % = 63 750,00.
  • Une restriction ne consomme jamais l'essai : un module coupe par la collecte seule peut retrouver son essai de 30 jours s'il n'avait jamais ete teste.
